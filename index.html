Three systems, three different problems

A live-streaming platform, an AI support layer, and the real-time messaging backbone underneath both.

Yogi Live

Real-time chat & live-streaming platform for astrology consultations
20K+daily consultations
5M+users served
99.9%uptime

The backend behind Astroyogi's live consultation product. A client's video/chat session is authenticated, routed through an API gateway, and handed off to SendBird and Agora SDK for the real-time layer, while .NET Core microservices built on Clean Architecture and CQRS handle session state, billing events and consultation history through Azure Service Bus. Redis absorbs hot read traffic; Cosmos DB holds the durable record.

Client (Web/Android/iOS)→ API Gateway + JWT/OAuth2→ Agora SDK / SendBird→ .NET Core microservices→ Redis+ Cosmos DB
stack: .NET Core · Azure Service Bus · SendBird · Agora SDK · Pusher · Redis · Cosmos DB · CQRS · Clean Architecture

AI Support Assistant

LLM-powered customer support with retrieval-augmented context
RAGcontext pipeline
Azurehosted

An end-to-end assistant built to take routine support volume off human agents. Incoming queries are embedded and matched against a vector store, the retrieved context and conversation history are assembled by LangChain, and the request is served through a FastAPI layer calling OpenAI and Claude/Anthropic models, deployed on Azure alongside the rest of the platform.

Support query→ Vector DB retrieval→ LangChain context→ FastAPI→ OpenAI / Claude API→ Response
stack: OpenAI API · Claude/Anthropic API · LangChain · RAG · FastAPI · Vector databases · Azure

VoIP & Real-Time Messaging Backbone

Queue-managed OBD/VoIP and notification layer
Millionsconcurrent connections

The shared infrastructure that Yogi Live and the wider platform call on for outbound dialing and push delivery: queue-managed OBD/VoIP calling, WebSocket-based live notifications, and webhook fan-out, sized to hold up under the same 5M-user load as the rest of the system.

Trigger event→ Message queue→ OBD/VoIP worker+ WebSocket push→ Firebase / Webhooks
stack: Azure Functions · WebSockets · Firebase · Webhooks · Queue management · .NET Core
